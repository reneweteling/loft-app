# Presigned URL Notes

Loft uses presigned GET URLs exclusively for the **Private pane** — files that should be accessible via a time-limited link without making the object or bucket public.

## What a presigned URL is

A presigned URL is a regular HTTPS URL for an S3 object with authentication credentials embedded directly in the query string, so any HTTP client can fetch the object without needing AWS credentials of its own. The URL is valid only until its expiry time; after that, S3 returns HTTP 403.

Presigned URLs are generated by the **client** (Loft), not by S3. S3 simply validates the embedded signature on each request.

## SigV4 expiry limit — 7 days

The maximum presigned URL expiry when signing with **SigV4** (the current AWS signing scheme) is **604,800 seconds = 7 days**. This is a hard cryptographic limit baked into the SigV4 specification — the `X-Amz-Expires` query parameter cannot exceed this value.

> [!warning] 7-day cap is non-negotiable
> S3 will return `AuthorizationQueryParametersError` for any presigned URL with `X-Amz-Expires > 604800`. Loft's UI clamps the expiry input to 7 days maximum. The older SigV2 scheme allowed longer expiries, but SigV2 is deprecated and not supported for new buckets.

The Private pane always generates 7-day presigned GET URLs. If longer-lived access is needed, the correct solution is to move to the Public pane (with CloudFront OAC) or a private CDN setup — not to presign with a longer expiry.

## Required query parameters

A SigV4 presigned URL carries authentication in these mandatory query parameters (in addition to any standard S3 query parameters):

| Parameter | Example | Purpose |
|---|---|---|
| `X-Amz-Algorithm` | `AWS4-HMAC-SHA256` | Identifies the signing algorithm |
| `X-Amz-Credential` | `AKIAIOSFODNN7EXAMPLE/20260423/us-east-1/s3/aws4_request` | Scoped credential: access key / date / region / service / terminator |
| `X-Amz-Date` | `20260423T120000Z` | ISO 8601 basic format, must match the date in the credential scope |
| `X-Amz-Expires` | `604800` | Seconds until expiry (max 604,800) |
| `X-Amz-SignedHeaders` | `host` | Semicolon-separated list of headers included in the signature |
| `X-Amz-Signature` | `<64 hex chars>` | Computed HMAC-SHA256 signature |

AWS SDK Swift's `createPresignedGetObjectRequest` generates all of these automatically.

## How presigning differs from a regular PUT

For a regular authenticated `PutObject`, credentials are carried in the `Authorization` HTTP header. For a presigned URL, credentials are moved into the query string so the URL is self-contained and sharable. The canonical request construction is identical (see [[SigV4 Signing]]) except:

1. The canonical query string includes the `X-Amz-*` parameters instead of them appearing in headers.
2. The `SignedHeaders` list is typically just `host` (the body is not signed — `X-Amz-Content-Sha256` is set to `UNSIGNED-PAYLOAD` for GET requests).
3. The resulting signature is appended as `X-Amz-Signature` in the query string.

```
Regular PUT (Authorization header):
GET /my-key HTTP/1.1
Host: my-bucket.s3.us-east-1.amazonaws.com
Authorization: AWS4-HMAC-SHA256 Credential=.../s3/aws4_request, SignedHeaders=host;x-amz-date, Signature=...
X-Amz-Date: 20260423T120000Z

Presigned GET (everything in query string):
GET /my-key?X-Amz-Algorithm=AWS4-HMAC-SHA256
           &X-Amz-Credential=...
           &X-Amz-Date=20260423T120000Z
           &X-Amz-Expires=604800
           &X-Amz-SignedHeaders=host
           &X-Amz-Signature=... HTTP/1.1
Host: my-bucket.s3.us-east-1.amazonaws.com
```

## Header whitelist

Only headers listed in `X-Amz-SignedHeaders` are protected by the signature. For a presigned GET URL, the standard approach is to sign only `host`. If you attempt to add other headers (e.g. `Range`) to a presigned GET request that did not include them in the signed headers, S3 will reject the request.

> [!info] No body signing for GET
> The payload hash for presigned GET URLs is always `UNSIGNED-PAYLOAD`. Signing the body would tie the URL to a specific response body, which is not useful for GET. The tradeoff is that a MITM could theoretically swap the response body — acceptable for content delivery over HTTPS where TLS provides transport integrity.

## Why private pane uses presigned URLs

The Private pane is designed for files that should not be publicly accessible. Options:

1. **Presigned URL** — bucket stays private; URL embeds credentials; expires after 7 days. No CDN required. Simple.
2. **Private CloudFront + signed cookies/URLs** — more operational complexity; appropriate for high-volume private delivery.
3. **Public-read ACL** — wrong; would expose the file to anyone who guesses the key.

Loft chooses option 1 for v1 simplicity. The 7-day expiry is acceptable for the use case (sharing a file with a specific person for a short period). After expiry the file still exists in the bucket and can be re-presigned from the history panel.

## Presigning with AWS SDK Swift

```swift
import AWSS3

let s3 = S3Client(config: clientConfig)

let presignedURLRequest = GetObjectInput(
    bucket: bucket,
    key: key
)

let presignedURL = try await s3.presignedURLForGetObject(
    input: presignedURLRequest,
    expiration: 604_800   // 7 days in seconds
)
// presignedURL is a Foundation URL ready to share
```

> [!warning] Credential rotation invalidates presigned URLs
> Presigned URLs embed the access key ID at signing time. If the IAM access key used to sign the URL is rotated or deleted, all previously issued presigned URLs for that key immediately become invalid — S3 will return 403. Plan key rotation accordingly or use temporary credentials (STS) if rotation is frequent.
